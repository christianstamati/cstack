## Develop

```bash
bun dev
```

<!-- cstack:if backend=convex -->
This runs `convex dev` and the web app together through Vite+ (`vp run`). The web app is on http://localhost:3000. The backend is a [local Convex deployment](https://docs.convex.dev/cli/local-deployments): it runs inside `bun dev`, keeps its data in `packages/backend/.convex`, and needs no Convex account.

`bun dev` runs `convex dev` without an interactive terminal, so it never asks to link the local deployment to your Convex account. To move development to a cloud deployment instead, run `bunx convex dev --configure` in `packages/backend`.
<!-- cstack:end -->

The web app is on http://localhost:3000.

## Environment

Convex deployment env vars. Set them in `packages/backend` with `bunx convex env set NAME`, which asks for the value:

| Variable | Purpose |
| --- | --- |
| `AUTH_PRIVATE_KEY`, `AUTH_JWKS` | Convex Auth signing keys (generated when the project was created) |
| `AUTH_GOOGLE_CLIENT_ID`, `AUTH_GOOGLE_CLIENT_SECRET` | Google OAuth client |
| `SITE_URL` | Web app origin that sign-in may redirect back to |

<!-- cstack:if frontend=tanstack-start -->
The web app reads `VITE_CONVEX_URL` from `packages/backend/.env.local`, which `convex dev` writes.
<!-- cstack:end -->

The web app reads `VITE_CONVEX_URL` from `packages/backend/.env.local`, which `convex dev` writes, and exposes it as `NEXT_PUBLIC_CONVEX_URL` (see `apps/web/next.config.ts`).

### Google sign-in

Create an OAuth client (Web application) at https://console.cloud.google.com/apis/credentials and add one authorized redirect URI per Convex deployment: `<CONVEX_SITE_URL>/oauth/google/callback`. For the local deployment that's `VITE_CONVEX_SITE_URL` from `packages/backend/.env.local`, like `http://127.0.0.1:3211/oauth/google/callback`.

## Going to production

The web app deploys to Vercel and the backend to Convex Cloud. This is a one-time setup; after it, every push to `main` deploys.

1. **Push to GitHub.** Create an empty repo, then:

   ```bash
   git remote add origin git@github.com:<you>/{{name}}.git
   git push -u origin main
   ```

2. **Create the Convex project.** In the [Convex dashboard](https://dashboard.convex.dev), create a project, open its production deployment's settings and generate a production deploy key.

3. **Configure the production backend.** With the deploy key in your shell, Convex commands target production:

   ```bash
   cd packages/backend
   export CONVEX_DEPLOY_KEY='<production deploy key>'
   bunx @convex-dev/auth                      # sets AUTH_PRIVATE_KEY and AUTH_JWKS
   bunx convex env set SITE_URL https://<your-app>.vercel.app
   bunx convex env set AUTH_GOOGLE_CLIENT_ID
   bunx convex env set AUTH_GOOGLE_CLIENT_SECRET
   unset CONVEX_DEPLOY_KEY
   ```

   Add the production deployment's redirect URI to your Google OAuth client: `https://<deployment>.convex.site/oauth/google/callback`.

4. **Create the Vercel project.** [Import the repo](https://vercel.com/new), set the root directory to `apps/web`, and add `CONVEX_DEPLOY_KEY` (the production key) as an environment variable for Production. `apps/web/vercel.json` provides the build command: `convex deploy` pushes the backend, then builds the web app against it.

5. **Match `SITE_URL`.** If Vercel gives the site a different URL, or you add a domain, set `SITE_URL` to it (step 3).

Preview deployments fail without a Convex deploy key for the Preview environment. Either add a preview deploy key from the Convex dashboard as `CONVEX_DEPLOY_KEY` for Preview, or turn preview deployments off in Vercel. Pull requests are checked by GitHub Actions (`.github/workflows/ci.yml`) either way.

## Going to production

The web app deploys to Vercel.

1. **Push to GitHub.** Create an empty repo, then:

   ```bash
   git remote add origin git@github.com:<you>/{{name}}.git
   git push -u origin main
   ```

2. **Create the Vercel project.** [Import the repo](https://vercel.com/new) and set the root directory to `apps/web`. Every push to `main` deploys after that, and pull requests get preview deployments.

Pull requests are also checked by GitHub Actions (`.github/workflows/ci.yml`).
<!-- cstack:end -->

Renovate (`renovate.json`) opens dependency PRs once the [Renovate GitHub app](https://github.com/apps/renovate) has access to the repo. Stable minor and patch updates merge automatically when CI passes.
