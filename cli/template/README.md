# {{name}}

TypeScript monorepo on TanStack Start and Convex, generated by `cstack new`.

## Develop

```bash
bun dev
```

This runs `convex dev` (backend) and Vite (web app on http://localhost:3000) together through Turborepo.

| Command | What it does |
| --- | --- |
| `bun dev` | Backend and web app in watch mode |
| `bun run test` | Backend tests (Vitest + convex-test) |
| `bun run typecheck` | `tsc` (TypeScript 7) in every package |
| `bun run check` / `check:fix` | Biome lint and format |
| `bun run build` | Production build of the web app |
| `bun run ui:add <component>` | Add a shadcn/ui component to `packages/ui` |

A lefthook pre-commit hook runs Biome on staged files.

## Layout

```
apps/web            TanStack Start app, deployed to Vercel
packages/backend    Convex functions, schema, auth and email (Convex Cloud)
packages/ui         shadcn/ui components on Base UI, Tailwind CSS 4
```

- Data fetching: TanStack Query through `@convex-dev/react-query`. `useQuery(convexQuery(api.x.y, args))` is a live subscription.
- Auth: Convex Auth v2 with Google sign-in. Routes under `apps/web/src/routes/_authed` require a signed-in user.
- Email: Resend through the `@convex-dev/resend` component (`packages/backend/convex/lib/email.ts`).
- The `tasks` table, `convex/tasks.ts` and the dashboard page are an example feature. Delete them when you start building.

## Environment

Convex deployment env vars (set with `bunx convex env set NAME` in `packages/backend`, add `--prod` for production):

| Variable | Purpose |
| --- | --- |
| `AUTH_PRIVATE_KEY`, `AUTH_JWKS` | Convex Auth signing keys (generated by `cstack new`) |
| `AUTH_GOOGLE_CLIENT_ID`, `AUTH_GOOGLE_CLIENT_SECRET` | Google OAuth client |
| `SITE_URL` | Web app origin that sign-in may redirect back to |
| `RESEND_API_KEY` | Resend API key. Without it, emails are logged instead of sent |
| `EMAIL_FROM` | Sender, e.g. `{{name}} <hello@example.com>` |
| `RESEND_WEBHOOK_SECRET` | Optional, for delivery status webhooks at `/resend-webhook` |

The web app reads `VITE_CONVEX_URL` from `packages/backend/.env.local`, which `convex dev` writes.

### Google sign-in

Create an OAuth client (Web application) at https://console.cloud.google.com/apis/credentials and add one authorized redirect URI per Convex deployment:

```
https://<deployment>.convex.site/oauth/google/callback
```

## Deploy

Pushing to `main` deploys to Vercel. `apps/web/vercel.json` runs `convex deploy` first, which pushes the backend to the production Convex deployment (using `CONVEX_DEPLOY_KEY`) and then builds the web app against it.

- Preview deployments are off, because only production has a Convex deploy key. Pull requests are checked by GitHub Actions (`.github/workflows/ci.yml`). To turn previews on, add a Convex preview deploy key as `CONVEX_DEPLOY_KEY` for the Preview environment in Vercel.
- When the production URL changes (e.g. a custom domain), update `SITE_URL` on the production deployment: `bunx convex env set SITE_URL https://example.com --prod`.
- Renovate (`renovate.json`) opens dependency PRs once the [Renovate GitHub app](https://github.com/apps/renovate) has access to this repo. Stable minor and patch updates merge automatically when CI passes.
